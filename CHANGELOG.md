# История изменений

Формат: версия, дата, список изменений (markdown). В конце блока — краткий текст поста для канала [@shaolenai](https://t.me/shaolenai) в комментарии `<!-- TELEGRAM_POST ... -->`. **Версия хранится только в репозитории** (файл `VERSION` и блок здесь); из Telegram-канала версия не читается. Служба публикации читает версию из `VERSION`, находит текст поста в этом файле и при появлении новой версии отправляет пост в канал через MTProto.

## [v1.1.6] — 2026-01-26

### Изменения

- **Google Calendar: без дубликатов** — при повторной выгрузке (синхронизации) привычки, цели и подцели больше не создают новые события в календаре. Сохраняется связь «сущность → событие» (таблица `calendar_events`). При изменении названия, даты, цвета и т.п. существующее событие обновляется (PUT), при первой выгрузке — создаётся (POST) и сохраняется его id. При удалении привычки, цели, подцели или миссии соответствующее событие удаляется из Google Calendar и запись из БД.

## [v1.1.5] — 2026-01-26

### Новое

- **Закрепление целей** — в меню редактирования цели добавлена возможность закрепить цель (кнопка «Закрепить» с иконкой keep). Закреплённые цели всегда отображаются сверху списка в порядке закрепления. Снять закрепление — кнопка «Открепить» (иконка keep_off). На карточке закреплённой цели отображается бейдж с иконкой keep.
- **Плашка приоритета** — вместо выпадающего списка «Низкий / Средний / Высокий» с эмодзи в диалоге создания и редактирования цели используется плашка из трёх сегментов: LOW (зелёный), MEDIUM (оранжевый), HIGH (красный) с треугольным указателем на треке под ней (по референсу). На карточке цели приоритет показывается компактной цветной плашкой вместо текстового бейджа.

### Изменения

- **Свайп по целям** — для активных целей свайп влево открывает две кнопки: «В архив» и «Удалить». Для целей в архиве — только «Удалить»; кнопка «Вернуть» остаётся видимой в строке.

## Как добавлять новые версии

1. **Запишите новую версию в файл `VERSION`** (одна строка, например `1.1.1`). Либо запустите `scripts/bump_version.py` (patch / minor / major).
2. В начале этого файла (после `---`) вставьте новый блок по образцу выше с той же версией (`v1.1.1` и т.д.).
3. Укажите дату в формате `YYYY-MM-DD`.
4. Опишите изменения в списке (markdown).
5. В конце блока добавьте комментарий:
   ```
   <!-- TELEGRAM_POST
   Краткий текст поста для канала (1–3 абзаца, эмодзи по желанию).
   -->
   ```
6. После деплоя скрипт публикации прочитает первую строку `VERSION`; если после версии **нет знака `+`**, отправит пост в канал и поставит `+`. Новая версия в `VERSION` добавляется следующей строкой (первой), предыдущая уходит ниже с `+` (удобно через `scripts/bump_version.py`).
